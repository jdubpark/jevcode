## Redaction details

- Rules (order matters; later rules never see earlier redacted spans): AWS access key IDs (`AKIA|ASIA|ABIA|ACCA` + 16), JWT (`eyJ` three-part), PEM private keys, `password|passwd|pwd=…`, `token|access_token|refresh_token|api_key|apikey|secret[:=]…`, `.env`-style uppercase `*KEY|TOKEN|SECRET|PASSWORD|PASSWD*=…` lines.
- Redacted spans are replaced with `[REDACTED:<kind>]`; the per-call count is aggregated into a `redaction` telemetry event.
- Secrets are never logged: jev-router constructs the TypeSafe SDK with `logLevel: "off"` and never logs the API key (typesafe-spike, §1). The redaction pipeline runs upstream of jev-router (typesafe-spike, §6.3).

## Known v0 bounds (explicit SPEC §3.7 decisions, not gaps)

- The agent process runs as the user's own account, cwd pinned to the repo root; no sandboxing in v0. Codex is spawned with `--dangerously-bypass-approvals-and-sandbox` by default (`packages/agent-codex/src/codex-adapter.ts`, `DEFAULT_SANDBOX_ARGS`), which is the documented v0 posture: the agent inherits the user's permissions. Override the sandbox args with the `JEVCODE_CODEX_SANDBOX_ARGS` env var (space-separated args; empty string disables the bypass flag). The `session:start` IPC payload accepts an optional `approvalMode` (`default` | `never` | `on-failure`) that maps to codex `approval_policy` config flags; the default is unchanged. Sandbox-args resolution is covered by `packages/agent-codex/src/codex-adapter.test.ts` ("resolves sandbox args...").
- Jevcode does not intercept arbitrary PTY commands in v0; destructive-command surfacing applies to agent-initiated commands that reach the evidence pipeline.
